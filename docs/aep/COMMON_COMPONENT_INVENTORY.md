## No shared package found

**Verified:** the root does not define a package workspace, and neither application imports source from a common package. Repeated React patterns are duplicated rather than shared. The separate apps' independent lockfiles and manifests reinforce that they build independently.

## Readiness against the requested reusable-component properties

| Property | Evidence-based finding |
|---|---|
| Clear inputs and outputs | **Partial:** typed props exist for UI helpers and typed records for event mapping. Many page-level workflows use callbacks, but cross-app contracts are duplicated and no general component API catalog exists. |
| Configurable properties | **Partial:** visual helpers accept props; product pages and charts are mostly authored directly in JSX. Notification rules are business configuration, not component configuration. |
| Data binding | **Not found in inspected code:** components import fixture modules or receive fully prepared records. No binding expression, schema registry, query descriptor, or runtime data source exists. |
| Loading, empty, error, missing-data states | **Partial:** empty states and missing-value text exist. Static prototypes do not demonstrate consistent async loading/error/retry states. |
| Consistent styling/accessibility | **Partial:** both apps have custom style systems; they differ. Some accessible labels, Escape handling, and semantic controls exist, but a cross-app accessibility contract and token package were not found. |
| Behavior and versioning | **Not found in inspected code:** no component manifest, compatibility policy, semver package, or registry exists. |
| Product-specific business logic isolation | **Partial:** LiftIQ alarm rules are in `logic/`; presentation pages still import product data directly. Notifications pages combine routes, UI, state and domain operations in one large file. |

## Reuse recommendation

Start with low-level, product-neutral primitives and contracts (tokens, page heading, table/filter primitives, empty/loading/error patterns, severity/status presentation with neutral input types). Keep alarm lifecycle decisions, telemetry calculations, workflow rules, and product-specific navigation in their product/domain layers. Avoid extracting a component solely because two screens look similar; define its data/state contract and verify both products can use it without adopting the same business model.
